# Design system

<!-- impeccable:design-system 1 -->

## Surface

Lecture notes book for reading and study. Mode: Read.

## Direction contract

- THESIS: Put twenty system design topics into one ordered study path. Refuse the landing-page pattern, decorative hero, and marketing copy.
- OWN-WORLD: Warm white paper, ink-black text, quiet blue navigation, and one orange accent for the current topic and source links. Use a plain system sans for all interface text and a readable system serif for note prose.
- STORY: The reader moves from system trade-offs to the network path, data and work, communication and trust, and interview practice. Each lecture states the idea, shows the path, maps it to AWS, asks a public interview question, and ends with a recall check.
- FIRST VIEWPORT: Book title and study instructions at the top of the content column. A persistent chapter index sits on the left on wide screens. The first lecture starts after orientation.
- FORM: Ordered lecture sequence with source notes, compact tables, semantic flow diagrams, AWS mapping, interview prompts, and native disclosure blocks. Staging: single-page book. Seed: not used; the brief fixes the reading form.

## Visual rules

- Use a restrained color strategy.
- Keep the reading measure between 65 and 75 characters when possible.
- Use borders for structure. Do not use decorative shadows, gradients, glass, or texture.
- Use existing repository diagrams only when they teach a relationship. Always include a text alternative.
- Use motion only for the current-section indicator. Keep content visible without motion.
- Keep all controls rectangular or lightly rounded. Use pills only for small metadata labels.
